# Autumn battlefield — 2026-10-29

Baseline: main `f02405844cd7dbd49deb20c55395ca465b22f89b`. Work started on an isolated branch; the ongoing online-presentation/UI branch was not merged or overwritten. No AGENTS.md was present. No combat balance, unit speed, AI, navigation algorithm, reservation invariant or UI card changes.

## Implementation

- Keep 176×128 and 350 soldiers/team. The explicit tactical skeleton still has two kingdoms, deployment/rear/front rooms, independent northern/southern flanks, four distinct entry destinations and rear counterattack connections.
- Protected main corridors widen from 18.31 to 21.74 tiles; flanks from 8.01 to 9.15; entries/counter routes from 6.86 to 9.15. Wider staging/merge rooms remain clear. Northern defense banks use a shorter angular ridge silhouette; southern banks use longer curved water silhouettes. Terrain still blocks movement through the existing forest/obstacle semantics. `visual: rock` is appearance only; no height, armor, cover or movement modifier is added.
- Global connected tiles remain `1 + x%5 + 5*(y%2)`, with no rotation/mirroring. Muted olive ground receives broad alpha patches, moss and leaves. North rock groups, southern reeds/lilies, kingdom paving and sparse remnants use the supplied art. The outer island has a continuous exposed side with a few rock accents; tall trees stay on blocked outer rim cells, away from reserved traffic.
- Supplied 48 PNGs are preserved byte-for-byte under `assets/world/autumn/source/`; `source-manifest.json` preserves their original hashes/crop provenance. Runtime atlas is bounded at 2048×1536 RGBA (12MiB decoded), 1,188,596 compressed bytes. A 1600×1000 distant forest is prebaked from the supplied trees, about 70KiB compressed / 6.1MiB decoded. The supplied package explicitly omitted a distant-background sheet. No external art or runtime blur was introduced.
- Terrain, patches, low scenery, distant image and cliff sides are baked into the existing padded viewport cache. An unchanged frame still makes one terrain-canvas copy. Cache dimensions/memory do not grow with map size. Walkable contour clipping is derived and cached once; clipping thousands of separate diamonds proved expensive and was removed during implementation.
- Scenery RNG is independent of tactical generation. Sprite placements are bounded at 480, held in WeakMaps and regenerated from seed/terrain on restore; no images or render caches enter snapshots. Original source PNGs are excluded from offline prefetch; runtime atlas/background/catalog are included.
- A seed29 real battle exposed an existing snapshot leak: `squadRoute.planner.staticSearch.open` contained a SearchQueue class. A narrow durable-state projection now drops only the transient shared planner, retaining route paths, commands and shared identity. Recovery rebuilds its incremental search normally. No Worker/peer/session protocol was changed.

## Measured validation

Files under `measurements/autumn-*` contain raw evidence; scripts reproduce the measurements.

- 32 seeds: terrain connectivity, complete reserved corridor cross-sections, turns, coast setback, deployment capacity, deterministic appearance and clear staging footprints. The obsolete 144×112 terrain-test expectation was corrected to 176×128, without lowering geometry assertions.
- `autumn-traffic-fixtures.json`: shared valid starts/destinations on old/new 176×128 maps; existing Board and squad orders, 180 simulated seconds, seeds7/29/73. Each main350, flank24, opposing48 and merge96 group crosses its passage. Zero occupancy/reservation collisions; maximum search expansions/tick never exceeds 2048. Flank/opposing/merge groups also fully settle. These are controlled engine traffic fixtures, not a claim that their synthetic 24-person main groups equal every current recruited roster.
- Main350 **does not fully settle** in either map. Before: 226/213/214 arrived; after: 223/225/230. Passage p95 before 76.05/79.45/79.80s; after 77.85/79.45/82.20s. Thus wider geometry is not a universal movement-speed improvement. Mean merge passage p95 improves from 47.47 to 43.65s, while opposing traffic varies by seed. Existing engine formation congestion remains unresolved; this terrain work does not claim to fix it.
- Real 700-unit combat uses the current equipment/stats/blueprints and commands, same seeds7/29/73, 60 simulated seconds each, three runs per map/seed (later runs alternate order). Zero collisions throughout. Median engine step p95 before→after: seed7 4.73→5.39ms, seed29 5.60→4.93ms, seed73 4.85→4.99ms. Seed7 is slower; a general CPU improvement or exact performance parity is **not** established. The per-seed simulation workloads also diverge as terrain changes combat. All remain well within the existing 50ms simulation interval on this machine; this is not a low-end-phone guarantee.
- One extended seed73 180s real battle/encoding run completes with zero collisions; engine-step p95 about4.21ms. This is not exhaustive long-duration stability testing.
- Initial uncompressed 700-unit checkpoint sizes decrease by roughly23–44KiB: appearance placements are not transmitted. Save/restore timings vary, including slower restores in some seeds. Round-trip tests verify matching regenerated appearance and preserved shared route identity, plus existing attack/healing/courtesy/in-flight movement recovery tests. Actual Internet/WebRTC reconnect was not rerun; no claim of deployed recovery testing.
- Browser cache measurements use the same seed, viewport and DPR for old/new modules. Mobile-size390×844 DPR2 terrain cache stays 11,369,600 bytes; desktop1280×800 DPR1 stays 6,488,064 bytes.
