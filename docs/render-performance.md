# 지형 렌더링 최적화

지형과 바닥 그림자는 카메라가 고정된 동안 뷰포트에 각 방향 128 CSS px의 여유를 더한 별도 Canvas에 보관합니다. 매 프레임에는 이 이미지를 한 번 복사하고 캐릭터·이펙트·선택 표시만 따로 그립니다. 캐릭터 애니메이션은 정지시키지 않습니다.

화면 크기·DPR 변경, 지형 수정·초기화, 타일 이미지 객체 교체 시 캐시를 다시 만듭니다. 카메라 조작 중에는 여유 영역을 재사용하고, 조작이 끝나거나 여유 영역을 벗어나면 갱신합니다. 지형 수정에는 `board.setTerrain(x, y, type)`을 사용합니다. 직접 배열을 바꾸는 외부 코드는 `terrainRevision`도 증가시켜야 합니다. 캐시 메모리는 지도 전체 크기가 아닌 화면의 물리 픽셀 수에 비례하며 렌더링 context마다 하나만 유지합니다.

캐시 재생성 시 역투영한 화면 범위로 행과 열 범위를 구합니다. 화면과 겹치는 타일만 모아서 기존 깊이·행 순서로 그리므로 측벽과 겹침 순서가 유지됩니다. 큰 지도 전체를 매번 순회하지 않습니다.

## 검증 결과

Chromium, 빈 128×128 전장(16,384타일), 1,000×700 화면, DPR 1에서 확인했습니다.

- 정지 카메라의 지형 drawImage 호출: 매 프레임 16,384회 → 캐시 이미지 1회.
- 캐시를 만들 때 그린 타일: 해당 카메라에서 237개.
- 캐시 RGBA 메모리: 4,802,944바이트. 지도 면적에 따라 커지지 않음.
- 5×16·128×128 전장, 확대율 .1/.7/2.4, DPR 1/2의 12개 장면: 이전 렌더러와 픽셀 차이 0.
- 같은 900×650 지형 장면의 JS 렌더 호출 측정: 이전 약 8.65ms, 캐시가 준비된 이후 약 .02ms. GPU 완료 대기나 병력 렌더링을 포함한 게임 FPS 수치가 아닙니다. 장치와 브라우저에 따라 달라집니다.

재현:

```sh
node --test tests/*.test.mjs
BASE_URL=http://127.0.0.1:8015 python3 tests/terrain-browser.py
BASE_URL=http://127.0.0.1:8015 python3 scripts/benchmark_terrain.py --baseline-ref 62c835a
```

`terrain-browser.py`는 재사용 횟수뿐 아니라 실제 지형 수정 픽셀, 이동·확대·초기화·리사이즈·DPR 변경 시 재생성을 확인합니다. `benchmark_terrain.py`는 지정한 Git 커밋의 원래 렌더러를 같은 브라우저에 로드해 비교합니다. 이번 범위는 정적 지형입니다. 많은 병력의 애니메이션 계산·정렬·충돌·경로 탐색은 이 타일 측정에 포함하지 않았습니다.


## 전체화면과 병력 렌더링

전장은 뷰포트 전체를 채우며 작은 메뉴·카메라 버튼·하단 테스트 조작부만 겹쳐 놓습니다. 사용 안내는 잠시 표시한 뒤 사라집니다. [화면](fullscreen-battlefield.jpg)을 참고하세요.

카메라 조작 중에는 캐시가 새 화면의 월드 영역을 덮는 한 좌표 이동과 배율 변환으로 재사용합니다. 여유 영역을 벗어나거나 지형이 바뀌면 재생성합니다. 카메라가 120ms 이상 정지하면 정확한 현재 좌표·배율로 다시 그려 임시 확대 샘플링을 정리합니다. 메모리는 지도 면적과 무관하게 여유 영역을 포함한 화면 크기에만 비례합니다.

파츠 계산 전에 캐릭터·장비의 보수적인 반경으로 화면 밖 병력을 제외하고, 남은 병력만 깊이 정렬합니다. 화면 밖으로 나간 인스턴스의 포즈 캐시는 해제합니다. 캐릭터 인스턴스별 포즈는 보통 30Hz, 축소 시 15Hz로 재사용하며 공격·피격·사망은 시간 정밀도를 유지합니다. 장착·건강 상태와 동작이 바뀌면 캐시가 갱신됩니다. 장비가 공통 채널을 그대로 쓰거나 무기 채널만 덮어쓰는 경우 전체 애니메이션 채널을 반복 계산하지 않습니다. 렌더러 밖의 편집기와 캐릭터 API는 기존처럼 정확한 시간으로 계산합니다.

화면 입력·카메라·지형이 변하면 즉시 다시 그립니다. 이동·전투·이펙트가 있으면 프레임 갱신을 유지하며, 보이는 대기 모션은 30Hz로 표시합니다. 화면 밖으로 카메라를 이동해 보이는 캐릭터·효과가 없어진 경우에는 캔버스를 계속 지우지 않습니다. 시뮬레이션 시간과 보이지 않는 캐릭터의 이동·사망 처리는 중단하지 않습니다.

1,000병력 시험 장면에서는 보수적 화면 판정으로 129개를 렌더링했고, 16ms 뒤 재사용 가능한 포즈 프레임에서는 추가 파츠 계산이 0회였습니다. 이 수치는 전체 전투의 FPS 보장이 아닌 해당 장면의 작업량입니다. `tests/immersive-browser.py`가 캐릭터 제외, 포즈 재사용, 이동·확대 중 지형 재사용, 정지 후 재생성, 변화 없는 빈 화면의 캔버스 clear 0회를 확인합니다.

기본검은 손별 반전·공격 회전 부호와 리그의 `equipmentRotations.basic_sword`로 목 안쪽 대신 바깥쪽을 향하게 합니다. 팔·몸통 레이어 규칙은 유지합니다. [양손 검 방향](sword-directions.jpg)에서 현재 여섯 캐릭터의 대기 자세를 확인할 수 있습니다.
