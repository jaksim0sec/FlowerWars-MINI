# 동시 이동

전체 전장에 걸린 동작 잠금을 없앴습니다. 다른 용사가 이동·공격 중이어도 선택한 용사에게 명령할 수 있습니다. 이동 중인 해당 용사의 동작을 끊지는 않으며, 경로 대기 중에는 새 명령으로 바꿀 수 있습니다. 목표 칸이 일시적으로 점유되어도 모델 명령은 유지됩니다. 일반 UI는 점유된 용사를 누르면 기존처럼 선택합니다.

## 알고리즘과 비용

- ID·현재 칸·다음 칸 예약을 Map으로 조회합니다. 한 걸음 동안 출발 칸과 도착 칸을 모두 보호합니다. 미래 경로 전체는 선점하지 않습니다. 정면 교환과 한 칸 중복 진입을 허용하지 않습니다.
- 장애물이 없으면 Manhattan 거리 공식으로 전역 탐색을 생략합니다. 장거리 맞대향 흐름이 있으면 방향별 통행 행/열을 나누어 교착을 줄입니다. 단독 이동에는 이 추가 우회를 적용하지 않습니다.
- 장애물이 있으면 목적지별 역방향 BFS 거리장을 재사용합니다. 최대 64개, 거리 배열 합계 약 4MiB 한도의 LRU입니다. 지도 한 장이 한도보다 크면 최소 한 장을 유지합니다. 진행 중 탐색 큐 한 장은 별도입니다. 다른 작업을 받기 전에 현재 탐색을 이어 끝내어 반복 초기화를 막습니다.
- 개체는 거리장 자체를 붙잡지 않고 자기 경로의 칸 번호만 보관합니다. 거리장이 캐시에서 나가도 매 걸음 재탐색하지 않습니다. 목표나 장애물 정보가 바뀌면 경로를 다시 구합니다.
- 의사 결정은 약 0.12초마다 진행합니다. 전체 탐색 확장을 주기당 2,048칸으로 제한합니다. 이 예산은 전역 BFS와 국소 우회가 공유합니다. 개체 하나의 국소 탐색은 96칸입니다. 예산이 없으면 대기합니다. 배열 초기화·경로 추출·개체 순회·렌더링 비용까지 제한하는 프레임 시간 보장은 아닙니다.
- 움직이는 앞 개체는 먼저 기다립니다. 계속 막히면 남은 경로에 다시 합류하는 짧은 우회나 옆 대피를 시도합니다. 대기 시간이 긴 개체 우선 + 순회 시작점 회전으로 고정 ID 우선순위를 피합니다. 재시도 간격을 늘려 막힌 개체가 매 프레임 BFS를 돌리지 않습니다. 대피로 경로에서 멀어지면 현재 위치에서 경로를 다시 연결합니다.
- 이동 보간·체력·타격·사망·명령 처리는 카메라와 무관합니다. 화면 밖에서도 동일하게 진행합니다. 피격 시 명령을 취소하되 살아 있는 용사는 예약한 한 걸음을 끝냅니다. 사망하면 칸과 예약을 즉시 해제하고 기존 사망 연출을 마칩니다.

완전한 다중 개체 최적 경로 해법은 아닙니다. 대피 공간 없는 맞대향 외길, 도착한 개체들이 완전히 둘러싼 목표 등은 길이 열릴 때까지 기다립니다. 정지한 다른 용사를 임의로 이동시키거나 장애물을 자동 공격하지 않습니다. 정적 장애물로 완전히 단절된 경로는 취소됩니다. 많은 서로 다른 목적지가 장애물 지도를 요구하면 탐색 예산에 따라 출발 대기가 늘어납니다.

## 테스트 메뉴

오른쪽 위 **이동 테스트** → 상황·개체 수 → **배치** → **동시 이동**. 교차·맞대향, 한 칸 병목, 장애물 우회, 대규모 이동을 16/64/256/1,000개체로 재현합니다. 배치는 현재 전장을 교체하며, **기본 전장** 또는 기존 초기화로 10×16 전장과 두 용사를 복원합니다. 목표 주변 통로를 남기는 배치입니다. 장애물은 어두운 × 칸입니다.

메뉴는 기본 접힘이며 열었을 때만 0.25초마다 이동·대기·도착 수, 누적 BFS 생성·우회 횟수, 최근 의사 결정 주기의 탐색 수를 갱신합니다. `대규모 이동`은 교차와 같은 알고리즘을 사용하며 개체 수로 부하를 바꿉니다.

## 확장 경계

```js
board.setObstacle(x, y, {blocked: true, kind: 'gate', attackable: true, hp: 100});
board.setObstacle(x, y, null); // 제거, 경로 캐시 무효화
board.movementPolicy = {
  beforeStep({board, unit, from, to, obstacle}) {
    return 'move'; // 'wait': 명령 유지, 'cancel': 취소
  },
  onArrive({board, unit, at}) {
    // 도착 칸의 조건, 이후 행동 요청 등을 처리하는 경계
  },
};
```

장애물의 추가 메타데이터는 보존합니다. `blocked:false`는 통과 가능합니다. 현재 칸이나 예약된 도착 칸에는 막는 장애물을 설치할 수 없습니다. 변경은 `setObstacle`로 해야 경로가 갱신됩니다. `beforeStep`은 실제 진입 직전 호출하며 결과를 결정할 때 현재 조건을 확인할 수 있습니다. 훅이 취소·피격·사망·전장 초기화 등을 일으켰으면 오래된 이동을 시작하지 않습니다. 장애물 공격 결정이나 자동 행동은 이번 범위에서 구현하지 않습니다.

`unit.command`: 이동 목적지 또는 공격 대상. `unit.step`: 진행 중 한 걸음. `unit.guide`: 남은 정적 경로의 칸 번호. `unit.route`: 짧은 국소 우회. `unit.waitReason`: traffic/planning/yielding/replanning/condition/unreachable. `board.navigation.stats`는 탐색 측정값입니다. 캐릭터 리그·장비·렌더링 엔진에는 이동 규칙을 넣지 않습니다.

## 검증 및 측정

```sh
node --test --test-isolation=none tests/*.test.mjs
node scripts/benchmark_navigation.mjs
BASE_URL=http://127.0.0.1:8018 python3 tests/navigation-browser.py
```

개발 환경 Node 모델 측정, 50Hz로 90초 모의 진행. 충돌 검사 비용은 update 측정에서 제외했으나 매 프레임 현재/예약 칸의 중복 여부를 검사합니다. 실제 브라우저 FPS·GPU·모바일 기기 성능 수치가 아닙니다.

| 설정 | 도착 | update p95 | 최대 탐색/주기 |
|---|---:|---:|---:|
| 교차 16 | 16/16 | 0.005ms | 100 |
| 병목 64 | 64/64 | 0.099ms | 2,048 |
| 장애물 64 | 64/64 | 0.083ms | 2,048 |
| 교차 256 | 256/256 | 0.026ms | 2,048 |
| 교차 1,000 | 1,000/1,000 | 0.499ms | 2,048 |

모델 테스트는 교차·맞대향·병목·대피 공간·막힌 외길·같은 목적지·이동 목표 추적·이동 중 피격/사망·장애물 갱신·캐시 퇴출·조건 훅을 확인합니다. 브라우저 테스트는 실제 키보드로 두 용사의 동시 이동, 카메라 밖 도착, 메뉴 배치/시작/복원, 모바일 터치를 검사합니다. 기존 전투·체력·지형 캐시·전체화면·모바일 회귀 검사도 실행합니다.
